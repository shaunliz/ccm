# ClaudeCodeMonitor

Claude Code 사용량 모니터. 트레이에 상주하며 세 지표(현재 세션 / 모든 모델 /
모델별)의 사용률을 주기적으로 조회해 차트와 게이지로 보여 주고, 임계치를 넘으면
윈도우 알림을 띄웁니다.

## 범위

두 개의 실행 파일로 나뉩니다.

**`ccm_probe`** — statusline 훅. 하는 일은 셋뿐입니다.

1. statusline 이 표준 입력으로 넘긴 JSON 을 읽는다.
2. 스냅샷 파일로 원자적으로 기록한다.
3. 한도 사용률 한 줄을 표준 출력으로 낸다.

**`ClaudeCodeMonitor`** — 트레이 상주 위젯 앱.

1. `claude` 를 띄워 `get_usage` 로 세 지표를 주기적으로 조회한다.
2. 표본을 쌓아 추이 차트를 그리고, 현재값을 게이지와 텍스트로 보여 준다.
3. 지표별로 여러 개 둔 임계치를 넘으면 윈도우 알림을 띄우고 목록에 쌓는다.
4. 로그인 시 자동 실행되며, 트레이 아이콘에 사용률을 숫자로 그린다.

## 디렉터리 구조

프로젝트 루트가 곧 포함 루트입니다. 소스는 `#include "core/..."`, `#include "infra/..."`
형태로 서로를 참조합니다.

| 디렉터리 | 역할 | 의존 |
|---|---|---|
| `core/` | 파싱, 임계치 판정, 문자열 생성. QObject 를 쓰지 않는 순수 값 객체와 함수 | Qt Core |
| `infra/` | 환경 의존 요소. 경로 결정, 파일 입출력, 설정, 레지스트리, 로깅 | Qt Core |
| `app/` | 훅 실행 진입점 | `core/`, `infra/` |
| `ui/` | 위젯 계층. QObject/QWidget 를 쓰는 화면과 서비스 | Qt Widgets, Qt Charts |
| `res/` | 아이콘과 Windows 리소스 스크립트 | - |
| `installer/` | NSIS 설치 스크립트와 DLL 수집 배치 | - |

`core/` 와 `infra/` 는 정적 라이브러리 `ccm_core` 로 묶여 두 실행 파일이 함께
씁니다. `ui/` 는 moc 가 필요하므로 `ccm_core` 가 아니라 위젯 타깃에 직접
들어갑니다. 루트의 `main.cpp` / `mainwindow.*` 도 위젯 타깃 것입니다.
빌드 구성은 루트 `CMakeLists.txt` 하나에 모여 있습니다.

## 스냅샷 파일 형식

`UsageSnapshot` 이 한도 사용률만 담는 것과 별개로, **파일에는 statusline 원본
payload 가 통째로 보존됩니다.** 위젯을 붙일 때 모델명, 컨텍스트, 비용 등을 파일에서
다시 꺼낼 수 있으므로, 파서를 줄였다고 해서 데이터가 사라지지는 않습니다.

```json
{
  "schemaVersion": 1,
  "capturedAt": "2026-09-11T01:42:08.614Z",
  "payload": { "...statusline 원본 그대로..." }
}
```

`capturedAt` 은 기록 시각(UTC)입니다. 스냅샷은 Claude Code 가 실행 중일 때만
갱신되므로, 읽는 쪽에서 이 값으로 신선도를 판단해야 합니다.

## 사용량 조회 경로 두 가지

한도 창을 얻는 길이 둘이고, **얻을 수 있는 창의 개수가 다릅니다.**

| 경로 | 창 | 비용 | 구현 |
|---|---|---|---|
| 스냅샷 (`infra/UsageQuery`) | 2개 | 공짜. 파일 한 번 읽기 | 훅이 남긴 파일을 읽는다 |
| claude CLI (`infra/ClaudeCli`) | 3개 이상 | 1~2초. claude 세션 1개 | `get_usage` 를 요청한다 |

### 스냅샷 경로가 2개인 이유

statusline 훅이 넘기는 payload 의 `rate_limits` 에는 `five_hour` 와 `seven_day`
두 개만 들어 있습니다. Claude 앱의 **사용량** 화면에 보이는 세 번째 줄, 즉 모델별
주간 창("Fable")은 이 payload 에 **아예 담기지 않습니다.** 파서가 버리는 것이
아니라 Claude Code 가 넣지 않습니다.

```
현재 세션      8%   <- five_hour
모든 모델      25%  <- seven_day
Fable          19%  <- statusline payload 에 없음
```

### CLI 경로가 세 번째 창을 가져오는 방법

statusline 은 푸시 방식이라 위젯이 원할 때 값을 요청할 수 없습니다. 요청할 수 있는
경로는 claude 의 SDK 용 control request 인 `get_usage` 입니다.

```
claude -p --input-format stream-json --output-format stream-json --verbose --strict-mcp-config
```

표준 입력으로 한 줄을 넣고,

```json
{"type":"control_request","request_id":"ccm_usage_1","request":{"subtype":"get_usage","skip_behaviors":true}}
```

표준 출력의 `control_response` 한 줄을 받습니다. 창은 세 갈래에서 나옵니다.

| 응답 필드 | 창 |
|---|---|
| `rate_limits.five_hour` | 현재 세션 (5시간) |
| `rate_limits.seven_day` | 주간 전체 (모든 모델) |
| `rate_limits.model_scoped[]` | 모델별 주간. `display_name` 을 서버가 준다 ("Fable") |

`seven_day_sonnet` / `seven_day_opus` 는 플랜에 따라 채워지는 고정 이름 창이며,
`null` 이 아닐 때만 목록에 들어갑니다. 즉 **창의 개수는 고정이 아닙니다.**
그래서 `UsageReport` 는 창을 목록으로 담습니다.

모델 호출이 없으므로 토큰 비용은 들지 않지만, 조회 1회에 claude 세션이 하나 뜨고
1~2초가 걸립니다. 사용자가 누를 때만 돌려야 합니다.

`get_usage` 는 SDK 내부 프로토콜이라 버전에 따라 바뀔 수 있습니다. 실패해도
스냅샷 경로는 그대로 동작하므로, 실패를 오류가 아니라 정상 경로로 다룹니다.

## Claude Code 상태줄

훅을 등록해 두면 Claude Code 화면 아래에 한 줄이 나옵니다. 그 글자를 만드는 것이
`ccm_probe` 입니다.

```
ClaudeCodeMonitor - Session : 40% | Model : 43% | Fable : 34%
```

색이 들어갑니다. 자세한 것은 아래 [색](#색) 절을 보십시오.

| 조각 | 어디서 오나 | 얼마나 신선한가 |
|---|---|---|
| `Session` | 훅이 받는 payload 의 `five_hour` | Claude Code 가 상태줄을 갱신할 때마다 (약 5초) |
| `Model` | 같은 payload 의 `seven_day` (모든 모델 주간) | 위와 같음 |
| `Fable` 등 | 위젯 앱이 남긴 캐시 | 앱의 폴링 간격만큼 (기본 5분) |

### 색

검은 바탕을 기준으로 골랐습니다. 터미널 기본 16색의 파랑은 검은 바탕에서 거의
읽히지 않으므로 쓰지 않고, 24비트 색으로 명도를 올려 잡았습니다. 채도는 낮추는
쪽입니다. 완전한 원색은 검은 바탕에서 번져 보이고 오래 보기 힘듭니다.

| 자리 | 색 | 값 |
|---|---|---|
| `ClaudeCodeMonitor`, `Session` | 파랑 | `#58A6FF` |
| `Model` | 보라 | `#BC8CFF` |
| 모델별 값 (`Fable` 등) | 초록 | `#4ADE80` |
| 구분자 `-` `\|` | 회색 | `#6E7681` |

구분자만 낮춘 이유가 있습니다. 셋 다 또렷하면 눈이 어디를 먼저 볼지 정하지 못합니다.
값이 앞에 서고 구분자가 뒤로 물러나야 한 줄이 세 덩이로 읽힙니다.

색을 끄는 길은 둘입니다.

| | |
|---|---|
| `--no-color` | 이 실행에서만 |
| `NO_COLOR` 환경 변수 | 여러 프로그램이 함께 지키는 약속이라 따른다 |

반대로 `--color` 는 `NO_COLOR` 가 있어도 색을 넣습니다. **훅 등록기가 이 인자를
붙여 등록합니다.** Claude Code 가 하위 프로세스에 `NO_COLOR` 를 물려줄 때가 있는데,
그것은 도구 출력물을 깨끗하게 받으려는 설정이지 상태줄을 위한 것이 아닙니다. 등록
명령에 적어 두면 환경이 어떻든 결과가 같습니다.

```json
"statusLine": {
  "type": "command",
  "command": "\"C:/.../ccm_probe.exe\" --color"
}
```

색이 싫으면 그 자리를 `--no-color` 로 바꾸면 됩니다.

**인자가 달라도 같은 실행 파일이면 우리 것으로 봅니다.** 예전에 `--color` 없이
등록해 둔 것을 "남의 설정" 으로 보면, 자기가 등록한 것을 두고 덮어쓸지 묻게 됩니다.
그것은 충돌이 아니라 갱신이므로 묻지 않고 인자만 고칩니다.

### 모델별 값은 왜 캐시를 거치나

두 실행 파일이 보는 것이 다릅니다.

```
훅 : Claude Code 의 payload      -> five_hour, seven_day 뿐
앱 : claude 의 get_usage 응답     -> 모델별 창까지 전부
```

상태줄에 `Fable : 34%` 를 적으려면 훅이 모델별 값을 알아야 하는데 그 값이 훅에게는
오지 않습니다. 그래서 앱이 조회에 성공할 때마다 모델별 값만 작은 파일
(`statusline.json`, 100바이트 남짓)에 적어 두고 훅이 읽어 뒤에 붙입니다.

훅이 직접 `claude get_usage` 를 부르는 방법은 쓰지 않습니다. 훅은 5초마다 도는데
조회 한 번에 claude 세션이 하나 뜨고 1~2초가 걸립니다.

캐시에는 **모델별 창만** 담습니다. `five_hour` 와 `seven_day` 는 훅이 payload 로
직접, 그것도 더 자주 받으므로 여기에 또 두면 어느 쪽이 참인지 흐려집니다.

### 앱이 꺼져 있으면 모델별 값은 사라진다

캐시는 앱이 멈추면 그대로 멈춥니다. 어제 값을 오늘 상태줄에 띄우는 것은 거짓말이므로,
**기록된 지 30분이 넘으면 없는 것으로 다룹니다.** 그러면 상태줄이 이렇게 줄어듭니다.

```
ClaudeCodeMonitor - Session : 40% | Model : 43%
```

30분은 폴링 간격(기본 5분)보다 넉넉하게 잡은 값입니다. 조회 한 번을 건너뛰었다고
글자가 사라졌다 나타났다 하면 눈에 거슬립니다.

낡음은 파일 수정 시각이 아니라 **파일 안에 적힌 시각**으로 봅니다. 내용이 같아도 다시
쓰면 수정 시각이 갱신되어, 낡은 값이 새것처럼 보이기 때문입니다.

## 화면

창은 위에서부터 세 칸입니다.

| 칸 | 내용 |
|---|---|
| 상태 표시등 | 빛 하나가 좌우로 오간다. 색은 사용량 수준, 움직임은 프로그램 상태 |
| 사용률 추이 (최근 24시간) | 지표별 꺾은선 + 임계치 점선(최대 3개). 자료원은 누적된 표본 |
| 현재 사용량 | 지표별 가로 막대. 색이 알림 수준(정상/경고/위험)을 따른다 |
| 요약 | 지표별 사용률과 재설정 시각, 플랜, 마지막 업데이트 시각, 자동 조회 간격 |

`get_usage` 는 "지금 값" 하나만 주므로 **과거는 우리가 쌓은 것밖에 없습니다.**
켠 직후에는 표본이 한 개뿐이라 선이 그려지지 않으며, 차트 아래에 그 사실을
알리는 문구가 뜹니다.

### 상태 표시등

창 맨 위에 빛 하나가 좌우로 오가는 띠가 있습니다. 전격 Z 작전의 키트 앞 램프와 같은
모양입니다.

**왜 두었는가.** 트레이에 상주하며 몇 분에 한 번 조회하는 프로그램입니다. 창을
열어도 숫자가 그대로면 "도는 중인데 값이 그대로인 것" 인지 "멈춘 것" 인지 알 수
없습니다. 움직이는 것이 하나 있으면 그 물음이 사라집니다.

살아 있다는 것만으로는 모자랍니다. 조회가 실패했거나 statusline 훅이 등록되지
않았으면 값이 낡아 가는데도 화면은 멀쩡해 보입니다. 그래서 무엇이 어긋났는지도 함께
말합니다.

#### 통로가 둘이고 서로 겹치지 않는다

| 통로 | 말하는 것 |
|---|---|
| **색** | 사용량 수준 (정상 파랑 / 알림 초록 / 경고 주황 / 위험 빨강) |
| **움직임 + 아이콘** | 프로그램 상태 (도는 중 / 조회 중 / 주의 / 오류) |

한 통로에 두 가지 뜻을 실으면 색이 답을 주지 못합니다. 처음에는 램프 색이 프로그램
상태였는데, 그러면 **주황이 겹쳤습니다.** "훅 미등록" 의 주황과 "경고 도달" 의
주황입니다. 빨강도 마찬가지로 "조회 실패" 와 "위험 도달" 이 겹쳤습니다. 빨간 램프를
보고도 글자를 읽어야 무슨 일인지 알 수 있었습니다.

그래서 색은 사용량에만 줍니다. 게이지와 트레이 아이콘이 쓰는 색과 정확히 같은 뜻이
되므로, 화면 어디를 보든 **빨강은 언제나 "사용량이 위험하다"** 입니다. 기준은 세
지표 중 가장 심각한 것이고, 트레이 아이콘이 쓰는 값(`UsageService::highestLevel()`)
그대로라 둘이 어긋날 일이 없습니다.

프로그램 상태는 움직임이 맡습니다.

| 상태 | 움직임 | 아이콘 | 글자 |
|---|---|---|---|
| 정상 | 천천히 오간다 (2.6초 왕복) | 없음 | 사용량 수준 이름 (`정상`/`알림`/`경고`/`위험`) |
| 조회 중 | 빠르게 오간다 (1.1초 왕복) | 없음 | `조회 중` |
| 주의 | 천천히 오간다 | 주황 세모 | `훅 미등록` |
| 오류 | **오가지 않는다.** 띠 전체가 숨 쉬듯 깜박인다 | 빨간 엑스 | `조회 실패` |

오류만 움직임이 다른 데에는 까닭이 있습니다. "움직이지 않는다" 는 것 자체가 멈췄다는
뜻으로 읽히므로, 오류를 색으로만 구분하지 않고 움직임으로도 구분합니다.

글자는 **자기가 말하는 통로의 색**을 씁니다. `훅 미등록` 은 프로그램 이야기이므로
왼쪽 세모와 같은 주황이어야 한 묶음으로 읽힙니다. 띠 색(사용량)을 쓰면 초록 띠 옆에
`훅 미등록` 이 초록으로 적혀 어느 쪽 말인지 흐려집니다.

걸리는 것이 없을 때 글자가 `정상` 이 아니라 사용량 수준 이름인 것도 같은 이유입니다.
빨간 램프 옆에 `정상` 이라고 적혀 있으면 어느 쪽을 믿어야 할지 알 수 없습니다.

차례가 곧 우선순위입니다. 조회 중이 맨 앞인 이유는, 실패한 뒤 다시 부르는 동안에도
"지금 고치는 중" 이 보여야 하기 때문입니다. 두 통로의 내용은 도구 설명에 글로도
함께 나옵니다.

빛이 끝에서 되돌아올 때 코사인을 씁니다. 일정한 속도로 튕기면 끝에서 딱 꺾여
기계적으로 보입니다. **창이 보이지 않으면 타이머를 멈춥니다.** 트레이로 내려가 있는
동안 30ms 마다 다시 그릴 이유가 없습니다.

훅 등록 여부는 남의 설정 파일(`~/.claude/settings.json`)이라 프로그램 밖에서도
바뀝니다. 그래서 조회할 때마다 다시 읽습니다. 작은 JSON 하나이고 몇 분에 한 번이라
값이 쌉니다. 그리기마다 읽지는 않습니다.

### 설정 창

항목이 늘어 한 화면에 세로로 늘어놓으면 창이 화면 높이를 넘습니다. 성격으로 갈라
탭 두 개에 담습니다.

| 탭 | 묶음 | 내용 |
|---|---|---|
| **알림 설정** | 알림 표시 | 윈도우 알림을 띄울지. 끄더라도 목록에는 쌓인다 |
| | 알림 임계치 | 지표별 규칙 표. 알릴지와 차트에 그릴지를 각각 확인란으로 고른다 |
| **환경 설정** | 조회 간격 | 자동 조회 간격 |
| | 시작과 종료 | 로그인 시 자동 실행, 트레이에서 시작, 닫기 동작 |
| | statusline 훅 | 훅 등록과 현재 등록 상태 |

가르는 기준은 **"언제 알릴 것인가"** 와 **"어떻게 동작할 것인가"** 입니다. 알림을
조정하러 열었을 때 시작프로그램 설정을 지나칠 필요가 없습니다.

설정 파일 안내와 **[저장] / [취소]** 는 탭 밖에 둡니다. 저장은 어느 탭을 보고 있든
두 탭의 내용을 함께 저장하므로, 탭 안에 있으면 그 탭만 저장되는 것으로 읽힙니다.

각 묶음의 차례에도 뜻이 있습니다. 알림 설정 탭은 켜고 끄는 스위치가 먼저, 세부
규칙이 나중입니다. 환경 설정 탭은 자주 만지는 것(조회 간격)이 위, 한 번 등록하면
다시 열 일이 없는 것(statusline 훅)이 아래입니다.

### 크기와 간격

아래쪽 버튼 세 개(**지금 조회 / 알림 관리 / 설정**)는 스타일이 정한 크기의 1.3배로
둡니다. 기준을 고정 픽셀이 아니라 `sizeHint()` 로 잡으므로 글꼴이나 테마가 달라져도
비율이 유지됩니다. 소수는 반올림합니다.

메뉴 표시줄은 `QMenuBar::item` 의 좌우 여백만 줄입니다. 윈도우 11 기본 스타일은
메뉴 제목 사이를 넓게 벌리는데, 항목이 둘뿐이라 **파일** 과 **도구** 가 멀찍이
떨어져 한 묶음으로 보이지 않습니다. 나머지 모양은 스타일이 정한 그대로 둡니다.

### 날짜 표기

모든 자리에서 `9월 15일(화) 23:00` 형태를 씁니다. 서식은 `core/TimeFormat` 한곳에
있습니다. 같은 시각이 화면 일곱 군데에 나오므로(게이지의 재설정 시각, 요약,
트레이 도구 설명, 팝업, 알림 목록, 차트 축) 자리마다 적으면 표기가 갈립니다.

**요일을 직접 붙이는 이유**는 Qt 6 의 `QDateTime::toString(format)` 이 요일과 달
이름을 영어로 채우기 때문입니다(`ddd` → `Tue`). 화면 글자가 모두 한글인데 요일만
영어로 섞이므로 표를 고정해 붙입니다. `QLocale` 을 끼우는 방법도 있지만 Qt 판이나
CLDR 판에 따라 약칭이 달라질 수 있습니다.

**오늘이어도 날짜를 적습니다.** 처음에는 오늘이면 시각만 보이게 했는데, 같은 값이
자리에 따라 다르게 보여(게이지는 `18:40`, 요약은 `9월 11일(금) 18:40`) 같은 것인지
헷갈렸습니다. 길어지더라도 한 형태로 갑니다.

예외가 하나 있습니다. **차트의 시간축에는 요일을 넣지 않습니다.** `QDateTimeAxis` 는
서식 문자열만 받고 그 자리를 Qt 가 영어로 채우므로, 숫자와 한글 리터럴만 써서
`9월 15일 23:00` 으로 냅니다. 눈금마다 요일이 붙으면 어차피 지저분합니다.

로그 타임스탬프(`yyyy-MM-dd HH:mm:ss.zzz`)와 설정 백업 파일 이름
(`settings.json.bak.<타임스탬프>`)은 그대로 둡니다. 사람이 읽는 화면 글자가 아니라
정렬과 파일 이름 규칙을 지켜야 하는 값입니다.

### 보조 설명 글자색

재설정 시각, 마지막 갱신 시각, 설정 화면의 안내 문구는 본문보다 여린 색으로
표시합니다. 처음에는 `QPalette::Disabled` 의 글자색을 그대로 썼는데, 그 색은
"쓸 수 없는 위젯" 을 나타내려고 만든 것이라 읽히기를 포기한 밝기입니다. 설명 문구는
읽어야 하는 글이므로 본문색을 섞어 한 단계 진하게 만듭니다. 완전히 진하게 가지
않는 이유는 그러면 설명과 본문이 구분되지 않기 때문입니다.

섞는 비율은 `ui/UiColors` 한곳에 있습니다. 비활성색(0)은 너무 여리고 0.55 는 본문과
잘 구분되지 않을 만큼 진해서, 지금은 0.3 을 씁니다. 이 색을 쓰는 자리가 다섯 군데라
자리마다 따로 계산하면 화면마다 밝기가 달라집니다.

### 차트를 갱신할 때 QChart 를 새로 만드는 이유

시리즈가 없는 상태로 차트가 처음 배치되면 축 눈금 글자 자리가 0 에 가깝게 잡히고,
뒤늦게 시리즈를 붙여도 다시 계산되지 않습니다. 그러면 눈금 숫자가 `...` 로 줄어든
채 남습니다. (창 크기를 바꾸면 정상으로 돌아오는 것이 근거입니다)
`layout()->invalidate()` 로는 풀리지 않으므로, 갱신할 때마다 시리즈를 갖춘 차트를
새로 만들어 끼웁니다. 선이 몇 개뿐이라 비용이 문제되지 않습니다.

같은 이유로 Y축 눈금은 숫자만 적습니다. `%` 까지 붙이면 좁은 창에서 글자 자리가
모자라 Qt Charts 가 다시 `...` 로 줄입니다. 단위는 칸 제목이 말해 줍니다.

## 트레이 상주

| 동작 | 결과 |
|---|---|
| 아이콘 보기 | 가장 심각한 지표의 사용률이 아이콘에 숫자로 그려진다. 색은 알림 수준 |
| 마우스 올리기 | 도구 설명에 세 지표, 마지막 업데이트 시각, 미확인 알림 건수. **즉시** 표시된다 |
| 한 번 누르기 | 팝업이 열리고 그때 새로 조회한다 |
| 두 번 누르기 | 창을 띄운다 |
| 우클릭 | 창 열기 / 지금 조회 / 알림 관리 / 설정 / 시작 시 자동 실행 / 종료 |

**마우스를 올릴 때는 조회하지 않습니다.** 조회 1회에 1~2초가 걸리므로 올릴 때마다
`claude` 를 띄우면 쓸 수 없습니다. 도구 설명은 마지막 조회값을 보여 주고, 실제
조회는 누를 때 합니다. 팝업도 먼저 마지막 값으로 채운 뒤 응답이 오면 갈아 끼우므로
빈 채로 떠 있지 않습니다.

### 닫기(X)를 누르면 묻는다

트레이 상주 프로그램의 닫기는 뜻이 둘입니다. "치워 두고 계속 돌려라" 와 "그만
써라". 어느 쪽인지 프로그램이 정해 버리면 반대를 원한 사용자는 매번 당황합니다.
그래서 팝업으로 묻습니다.

| 선택 | 동작 |
|---|---|
| **백그라운드에서 계속** | 창만 숨기고 트레이에서 계속 조회·알린다 (기본 선택) |
| **완전 종료** | 조회와 알림을 모두 멈춘다 |
| **취소** | 닫지 않는다. Esc 도 여기로 걸린다 |

닫기는 실수로도 눌리고, 되돌릴 길이 없으면 조회 이력이 끊기므로 취소를 함께 둡니다.

팝업의 **다시 묻지 않음** 을 켜면 그때 고른 동작을 기억해 다음부터
바로 그렇게 합니다. 끄기만 저장하고 무엇을 할지 적지 않으면 그 뒤로 닫기를 눌렀을
때 무슨 일이 일어날지 알 수 없게 되므로, 동작까지 함께 저장합니다.

**취소와 함께 켠 체크는 무시합니다.** "묻지 말고 앞으로 취소해라" 는 뜻이 성립하지
않습니다.

다시 묻게 하려면 설정 창의 **시작과 종료 > 창을 닫을 때 어떻게 할지 물어보기** 를
켭니다. 그 아래에 현재 어떻게 동작하는지(묻는지, 아니면 트레이 유지인지 완전
종료인지)가 한 줄로 나옵니다. 끄기만 보여 주면 닫기를 눌러 봐야 알 수 있기
때문입니다.

파일 > 종료와 트레이 메뉴의 종료는 뜻이 분명하므로 묻지 않습니다. 트레이를 쓸 수
없는 환경에서는 숨을 곳이 없으므로 닫기가 곧 종료이고, 고를 것도 없어 묻지
않습니다.

**단일 인스턴스입니다.** 시작프로그램 등록과 수동 실행이 겹쳐 트레이 아이콘이 두 개
뜨는 것을 막기 위해, 나중에 뜬 쪽은 먼저 뜬 쪽에 창을 띄우라고 알리고 물러납니다.

## 임계치와 알림

### 알림 수준은 세 단계다

| 수준 | 아이콘 | 색 |
|---|---|---|
| (기본) | 없음 | **파랑** — 임계치를 하나도 넘지 않은 상태 |
| **알림** | 느낌표 | **초록** |
| **경고** | 세모 | **주황** |
| **위험** | 엑스표 | **빨강** |

파랑 → 초록 → 주황 → 빨강 순으로 올라갑니다. 게이지 막대, 아이콘, 차트의 임계치
점선이 모두 같은 색을 씁니다. 아이콘 색을 따로 정하면 막대는 초록인데 아이콘은
파란 상황이 생기므로 `levelColor` 하나만 봅니다.

아이콘은 파일로 두지 않고 그때그때 그립니다. 리소스와 배포 목록이 늘지 않고 화면
배율이 달라도 또렷합니다. 정의는 `ui/AlertVisuals` 한곳에 있고 게이지, 차트,
알림 목록, 윈도우 알림이 모두 여기서 가져갑니다. 곳마다 다르면 사용자가 같은 것을
다른 것으로 읽기 때문입니다.

**색만으로 구분하지 않습니다.** 색만 쓰면 색약인 사용자와 흑백 화면에서 세 수준이
같아지므로, 수준마다 색과 모양을 함께 바꿉니다. 게이지에서도 사용률 왼쪽에 아이콘이
붙습니다.

내부에는 `정상` 수준이 하나 더 있지만 규칙에 쓸 수 없습니다. "임계치를 하나도 넘지
않은 상태" 를 뜻하며 게이지와 트레이 아이콘 색에만 쓰입니다. (채도를 낮춘 회청색)

### 지표 하나에 임계치를 여러 개 둔다

"현재 세션 70% 에 알림, 85% 에 경고, 95% 에 위험" 처럼 단계를 쌓을 수 있습니다.
규칙마다 수준을 따로 정하며 개수 제한은 없습니다.

설정 창의 임계치 표는 `알림 활성 | 차트 표시 | 지표 | 사용률 | 수준` 다섯 열이고,
**알림 추가 / 선택 알림 삭제**
로 늘리고 줄입니다. 지표를 칸으로 나누지 않고 한 열로 둔 이유는, 지표 수가 계정에
따라 달라지고 규칙 수도 지표마다 다르기 때문입니다. 표 한 개면 둘 다 그대로 받아
냅니다.

#### 알리는 것과 그리는 것은 다른 스위치다

규칙 한 줄에 확인란이 둘 붙습니다.

| 열 | 뜻 | 개수 제한 |
|---|---|---|
| **알림 활성** | 이 임계치를 넘으면 알린다 | 없음 |
| **차트 표시** | 이 임계치를 차트에 점선으로 긋는다 | 최대 3개 |

처음에는 확인란이 하나(차트 표시)뿐이었습니다. 그러다 보니 그것을 끄면 알림까지
꺼지는 것으로 읽혔습니다. 실제로는 상관이 없는데도 그렇게 보였습니다. 둘로 나눠
두면 "알리지는 말고 선만 보겠다" 와 "알리되 선은 긋지 말라" 가 둘 다 됩니다.

차트 표시에만 개수 제한이 있는 것은 화면이 좁기 때문입니다. 알림은 몇 개를 켜도
화면을 차지하지 않습니다.

꺼 둔 규칙은 `AlertEvaluator` 가 아예 건너뜁니다. 알리지 않을 뿐 아니라 게이지와
트레이 아이콘 색을 정하는 수준 계산에도 세지 않고, 이미 알렸다는 표식도 남기지
않습니다. 다시 켜면 그 구간에서 한 번 알립니다.

**기본값은 지표마다 "70% 에 알림" 한 줄뿐입니다.** 종류에 따라 다르지 않습니다.

처음부터 여러 단계를 깔아 두면 켜는 순간 지표마다 알림이 여러 건 쌓여 목록이
시끄럽습니다. 필요한 단계는 설정 화면에서 더합니다.

### 규칙은 창 키에 붙고, 없으면 종류 기본값을 쓴다

화면에는 `Fable (주간)` 처럼 서버가 준 실제 창 이름이 보여야 하므로 설정은 창
키(`model:Fable`)에 붙습니다. 다만 모델별 창은 계정 사정에 따라 새로 생길 수
있으므로, **설정이 없는 창은 종류 기본값으로 동작합니다.** 모델이 하나 늘었을 때
알림이 조용히 빠지는 것을 막기 위함입니다.

한 지표의 줄을 **모두 지우면** 그 지표는 알리지 않습니다. (기본값으로 되돌아가지
않습니다)

### 한 번 알린 것은 다시 알리지 않는다

사용률은 한 번 올라가면 재설정 때까지 내려오지 않습니다. 통과 사실만 보고 알리면
같은 알림이 재설정 시각까지 폴링마다 반복됩니다. 그래서 **(창, 임계치, 그 창의
재설정 시각)** 을 표식으로 기억하고, 같은 조합이면 건너뜁니다. 표식은 설정 파일에
남으므로 프로그램을 다시 켜도 반복되지 않습니다.

표식이 지워지는 경우는 둘입니다.

1. 창의 재설정 시각이 바뀌었다 → 새 구간이므로 다시 알린다.
2. 사용률이 그 임계치 아래로 내려갔다 → 조건이 풀렸으므로 다시 넘으면 알린다.

사라진 창의 표식도 함께 버립니다.

### 알림이 가는 곳 두 군데

| 경로 | 보관 | 지우는 주체 |
|---|---|---|
| 윈도우 알림 (토스트) | 알림 센터(시계를 누르면 나오는 쪽)에 쌓인다 | 사용자가 지우면 사라진다. OS 가 관리 |
| 프로그램의 **알림 관리** 창 | 파일에 누적된다 | 프로그램에서 확인/삭제한다 |

앞쪽은 OS 가 관리하므로 확인하면 그것으로 끝입니다. 뒤쪽은 따로 남으므로 자리를
비운 동안 뜬 알림도 나중에 볼 수 있습니다.

차트의 지표별 선 색은 수준 색과 쓰임이 다릅니다(지표를 구분하는 색). 다만 주황과
빨강은 그 팔레트에서 뺐습니다. 경고 임계치 점선과 헷갈리고, 선이 빨갛다는 것만으로
위험해 보이기 때문입니다.

윈도우 알림에도 수준 아이콘이 그대로 붙습니다. Qt 가 주는 기본 아이콘은
정보/경고/위험 셋뿐이라 우리 세 수준의 모양과 맞지 않으므로, 직접 그린 아이콘을
넘깁니다.

알림이 알림 센터에 **앱 단위로** 묶이도록 시작할 때
`SetCurrentProcessExplicitAppUserModelID` 로 신원을 밝힙니다. 이것을 정해 두지
않으면 실행 파일 경로에 따라 다른 앱으로 취급되어, 설치 위치가 바뀌면 이전 알림과
묶이지 않습니다. 설치 관리자가 만드는 시작 메뉴 바로가기와 짝이 되는 값입니다.

한 번의 조회에서 여러 임계치를 동시에 넘을 수 있습니다. 그만큼 알림을 쪼개 띄우면
알림 센터가 도배되므로 **한 건으로 묶어** 띄웁니다. 프로그램의 알림 목록에는 통과한
임계치마다 한 줄씩 남습니다.

### 차트의 임계치 점선

지표마다 임계치가 여러 개이고 값도 서로 다르므로 전부 그으면 화면이 선으로 덮입니다.
그래서 **골라서** 긋습니다. 설정 창 임계치 표의 **차트 표시** 열에서 확인란으로
**최대 3개**까지 고릅니다. 지표가 셋(세션 / 모든 모델 / 모델별)이므로
지표마다 하나씩 고를 수 있는 만큼입니다.

세 개가 차면 나머지 확인란이 잠깁니다. 잠그지 않으면 네 번째를 눌렀을 때 아무 일도
일어나지 않는 것처럼 보입니다. 표 아래에 `최대 3개까지, 지금 N개를 골랐습니다` 를
함께 적어 잠긴 이유를 알립니다.

아직 고른 적이 없거나 고른 줄을 모두 지웠으면 **가장 먼저 닿는 임계치** 하나로
되돌아갑니다. 수준을 가려 고르지는 않습니다. 기본 설정에는 알림 규칙만 있어서
경고만 찾으면 선이 아예 사라지기 때문입니다.

#### 점선 색은 수준이 아니라 지표를 따른다

점선 색을 수준 색(알림 초록, 경고 주황, 위험 빨강)으로 칠하지 않습니다. 고른 셋이
모두 "알림" 이면 점선 세 개가 같은 초록이 되어 어느 지표의 것인지 알 수 없기
때문입니다. `70%` 라는 숫자는 **어느 지표의** 70% 인지를 알아야 뜻이 생깁니다.

그래서 그 임계치가 속한 지표와 **같은 차례의 원색**으로 긋습니다. 꺾은선 색을 그대로
쓰지 않는 것은 범례 때문입니다. 같은 색 실선과 점선이 나란히 놓이면 작은 네모 견본만
보고 가려내기 어렵습니다. 자리(세션은 파랑 계열)는 지키고 채도만 올려, 꺾은선은
차분하게 점선은 또렷하게 둡니다.

#### 범례 이름은 짧게, 그리고 서로 달라야 한다

범례는 이름이 가로로 늘어서는 자리입니다. 꺾은선 셋에 점선 셋이면 이름이 여섯 개
붙으므로, `현재 세션` / `모든 모델 (주간)` / `Fable (주간)` 을 그대로 쓰면 범례가
여러 줄로 접히고 차트가 눌립니다. `core/WindowLabel` 이 **세션 / 모델 / Fable** 로
줄인 이름을 줍니다. 게이지와 요약처럼 한 줄을 통째로 쓰는 자리는 원래 이름 그대로입니다.

점선은 거기에 `임계치` 를 붙여 **세션임계치 / 모델임계치 / Fable임계치** 로 적습니다.
처음에는 `세션 70%` 처럼 숫자를 붙였는데, 범례에 `세션` 과 `세션 70%` 가 나란히
놓이니 이름이 같아 보이고 숫자만 다른 꼴이 되었습니다. 숫자는 점선의 높이와 세로축이
이미 말해 줍니다.

#### 첫 열의 너비

`QCheckBox::sizeHint().width()` 와 머리글 글자 너비 중 큰 쪽으로 잡습니다.
`PM_IndicatorWidth` 는 네모 한 변만 주므로 테두리와 초점 테두리가 들어갈 자리가
없어 오른쪽이 잘립니다. 칸 안쪽에도 좌우 여백을 둡니다. 여백이 0 이면 네모가 칸
가장자리에 닿습니다.

지표 열은 내용이 짧아 필요한 만큼만 주고, 남는 폭은 마지막 열이 가져갑니다.

### 알림 관리 창

| 동작 | 설명 |
|---|---|
| 확인 / 미확인 구분 | 미확인 줄은 굵게. 첫 열에 상태가 글자로도 표시된다 |
| 수준 표시 | 수준 열에 아이콘과 색이 함께 나온다 |
| **선택 확인** / 줄 두 번 누르기 | 고른 줄을 확인 처리한다. 목록에는 남는다 |
| **모두 확인** | 전부 확인 처리한다 |
| **선택 삭제** | 고른 줄만 지운다. 여러 줄을 함께 고를 수 있다 |
| **전체 삭제** | 목록을 비운다. 미확인이 섞여 있으면 그 건수를 알리고 확인받는다 |

확인과 삭제는 다른 동작입니다. 확인은 "봤다" 이고 목록에 남으며, 삭제는 목록에서
없앱니다. 둘을 한 버튼으로 묶으면 이력을 남기려는 쪽과 치우려는 쪽 중 하나는
불편해집니다.

미확인 건수는 메인 창의 **알림 관리 (N)** 버튼과 트레이 도구 설명에도 나옵니다.

목록은 최근 것이 위로 옵니다. 넣는 순서에 기대지 않고 저장소가 매번 시각순으로
정렬합니다. 앞에 끼우는 방식으로 두었더니 한 번의 조회에서 나온 알림들끼리 순서가
뒤집혀 오래된 것이 위로 올라왔습니다.

목록은 최대 500건을 보관하고 **확인한 것부터** 버립니다. 보지 못한 알림을 조용히
버리면 알림의 뜻이 없기 때문입니다. 미확인만으로 상한을 넘기면 그때는 가장 오래된
것부터 버리고 그 사실을 로그에 남깁니다.

## 자동 조회

기본 5분 간격이며 설정에서 바꿉니다. 0 으로 두면 자동 조회를 하지 않습니다.

조회 1회에 `claude` 세션이 하나 뜨고 1~2초가 걸립니다. **모델을 호출하지 않으므로
토큰 비용은 들지 않습니다.** 다만 프로세스가 뜨는 비용이 있으니 너무 짧게 두지
않는 편이 낫습니다.

조회는 비동기입니다. `QProcess` 시그널로 받으므로 스레드를 쓰지 않으며, 조회 중에도
화면이 멈추지 않습니다. 조회가 진행 중인데 또 요청이 오면(연타하거나, 폴링과 수동
조회가 겹치거나) 무시합니다.

## 시작프로그램 등록

**처음 실행할 때 자동으로 등록됩니다.** 설정에서 끄거나 트레이 메뉴에서 토글할 수
있고, 한 번 끄면 다시 켜지지 않습니다.

등록 위치는 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 입니다.
후보가 셋 있었습니다.

| 방법 | 문제 |
|---|---|
| 시작 폴더 바로가기 | 파일이라 사용자가 지우면 흔적 없이 사라진다 |
| 작업 스케줄러 | 권한 상승이 필요하고 설정이 무겁다 |
| **HKCU Run 키** | 관리자 권한이 필요 없고, 작업 관리자의 "시작 앱" 에 그대로 보인다 |

사용자 단위 프로그램이므로 마지막을 씁니다. HKLM 은 쓰지 않습니다. 권한 상승이
필요하고 다른 사용자에게까지 등록됩니다.

**직접 실행할 명령이 아닙니다.** 설정 창의 `로그인 시 자동 실행` 확인란을 켜고
저장하면 그 명령이 레지스트리에 등록되고, 그것으로 끝입니다. statusline 훅 등록과
달리 따로 눌러 실행할 것이 없습니다. 설정 창에는 지금 등록 상태와 등록될 명령이
함께 보이며, 등록된 명령이 지금 실행 파일과 다르면(설치 위치를 옮겼거나 다른
빌드로 등록해 둔 경우) 그 사실을 알립니다. 그대로 두면 없는 파일을 가리키는 항목이
시작 앱 목록에 남기 때문입니다.

등록되는 명령에는 `--tray` 가 붙습니다. 로그인 직후 창이 튀어나오지 않게 하기
위함입니다. 경로는 반드시 따옴표로 감쌉니다. 감싸지 않으면 공백이 있는 경로에서
OS 가 `C:\Program` 을 실행하려 합니다.

## 디버그 콘솔

GUI 앱이라 콘솔이 없습니다. 그래서 트레이에서 조용히 도는 동안의 문제를 쫓는
방법이 `monitor.log` 를 열어 보는 것뿐이었습니다. **도구 > 디버그 콘솔** 을 켜면
콘솔 창이 붙고 로그가 눈앞에서 흐릅니다. 끄면 떨어집니다.

**릴리즈 빌드에서도 동작합니다.** 디버그 전용 장치가 아닙니다.

| 근거 | 설명 |
|---|---|
| `AllocConsole` | 평범한 Win32 API 다. `/SUBSYSTEM:WINDOWS` 로 링크되어 시작할 때 콘솔이 없을 뿐, 실행 중에 붙이는 것은 막혀 있지 않다 |
| `qCDebug` 가 살아 있다 | Qt 가 로그를 컴파일 단계에서 지우는 것은 `QT_NO_DEBUG_OUTPUT` 이 정의될 때뿐이다. 릴리즈가 주는 `QT_NO_DEBUG` 는 `Q_ASSERT` 만 없앤다 |
| 로거를 고치지 않아도 된다 | `infra/Logger` 가 이미 모든 줄을 UTF-8 로 `stderr` 에 쓴다. 콘솔을 붙이고 `stderr` 를 그리로 다시 열면 그대로 흐른다 |

### 무엇이 나오는가

콘솔을 열어도 보여 줄 것이 없으면 소용이 없습니다. 조회 한 번의 처음부터 끝까지,
설정을 저장한 내용, 어긋난 구간의 사정을 남깁니다.

| 구간 | 수준 | 남기는 것 |
|---|---|---|
| 시작 | DEBUG | 이력 표본 수, 알림 건수, 표식 수, 임계치를 설정한 지표 |
| 조회 시작 | DEBUG | 실행 파일, 인자, pid, 보낸 요청 바이트, 대기 제한 |

### 콘솔 창을 닫으면 프로그램이 함께 죽는다

콘솔을 닫으면 `CTRL_CLOSE_EVENT` 가 오고, 처리기가 무엇을 하든 윈도우가 곧
프로세스를 끝냅니다. `SetConsoleCtrlHandler` 로 참을 돌려주어도 유예 시간이 지나면
종료됩니다. **막을 방법이 없습니다.**

그래서 두 가지로 막습니다.

1. 콘솔 시스템 메뉴에서 `SC_CLOSE` 를 지워 닫기 단추를 없앤다.
2. 여는 순간 콘솔 첫 줄에 그 사실을 적는다.

윈도우 터미널이 기본 터미널이면 `GetConsoleWindow` 가 실제 창을 주지 않아 1번이
듣지 않습니다. 그때는 2번이 유일한 수단입니다.

### 여는 동안 로그 수준을 올린다

기본 수준이 `정보` 라 콘솔을 열어도 `qCDebug` 는 걸러져 빈 창만 보입니다. 콘솔을
여는 목적이 대개 자세히 보려는 것이므로, 열 때 `디버그` 로 올리고 이전 수준을
기억해 두었다가 닫을 때 되돌립니다. 그동안 `monitor.log` 에도 디버그 줄이 함께
쌓입니다.

### 한글이 깨지지 않게

콘솔 기본 코드페이지는 한국어 윈도우에서 CP949 입니다. 로그는 UTF-8 로 나가므로
`SetConsoleOutputCP(CP_UTF8)` 로 맞춰 줍니다. `ccm_probe` 도 자기 콘솔에 같은
처리를 합니다.

## 데이터 파일

모두 `%LOCALAPPDATA%\ClaudeCodeMonitor\` 아래에 있습니다.

| 파일 | 내용 |
|---|---|
| `snapshot.json` | statusline 훅이 남긴 원본 payload |
| `settings.ini` | 폴링 간격, 지표별 임계치 목록, 차트에 그릴 임계치 목록, 알림 설정, 종료 동작, 이미 알린 것의 표식 |
| `history.json` | 사용률 표본. 7일 보관, 차트가 최근 24시간을 읽는다 |
| `alerts.json` | 알림 목록. 확인 여부 포함. 최대 500건. 스키마 3 |
| `monitor.log` | 위젯 실행 로그 |

수준이 셋으로 늘면서 `alerts.json` 의 수준 정수값이 한 칸씩 밀렸습니다
(경고 1 → 2, 위험 2 → 3). 스키마 2 로 적힌 파일은 읽을 때 옮기고 곧바로 다시
기록합니다. 그러지 않으면 예전 "경고" 가 "알림" 으로 보입니다.

설정을 레지스트리가 아니라 INI 로 두는 이유는 설치 관리자가 지우기 쉽고, 문제가
생겼을 때 사용자가 직접 열어 볼 수 있기 때문입니다. 시작프로그램 등록만은 OS 가
정한 자리가 있으므로 레지스트리를 씁니다.

규칙 한 조각은 `70.0:notice` 이고, 꺼 둔 줄에만 꼬리표가 하나 더 붙습니다
(`85.0:warn:off`). 대부분의 줄이 켜져 있으므로 켠 쪽을 짧게 두어야 파일이 읽기
쉽고, 꼬리표가 없는 줄을 켜진 것으로 읽으면 예전 파일도 그대로 열립니다.

차트에 그릴 임계치는 `ui/chartThresholds` 에 목록으로 적습니다. 한 조각이
`70.0:five_hour` 형태이고, **사용률이 앞**입니다. 창 키에는 `:` 가 들어가므로
(`model:Fable`) 키를 앞에 두면 어디서 잘라야 할지 알 수 없지만, 숫자를 앞에 두면
언제나 첫 `:` 에서 자르면 됩니다.

한 줄만 고를 수 있던 시절에는 `ui/chartThresholdWindow` 와
`ui/chartThresholdPercent` 두 키를 썼습니다. 새 키가 **없을 때만** 그 둘을 읽어
옮기고, 다음 저장에서 지웁니다.

**빈 목록과 없는 키는 다릅니다.** 빈 목록은 "하나도 그리지 말라" 는 사용자의 뜻이고,
키가 없는 것은 "아직 고른 적이 없다" 입니다. 앞은 그대로 따르고, 뒤는 가장 먼저 닿는
임계치 하나를 대신 그려 줍니다. 처음 켠 화면에 기준선이 하나도 없으면 높낮이만
보이기 때문입니다. 이 구별을 `chartThresholdsConfigured()` 가 맡습니다.
(빈 목록이 파일에 `@Invalid()` 로 적히는 것은 QSettings 의 표기입니다)

**GUI 앱이라 콘솔이 없습니다.** 그래서 로그를 `monitor.log` 에도 남깁니다. 트레이에서
조용히 도는 동안의 문제를 추적할 방법이 파일뿐입니다. Qt Creator 에서 실행하면
Application Output 창으로도 보입니다. 한글이 깨져 보이면 출력 인코딩을 UTF-8 로
맞추십시오.

## 설치 관리자

`installer/` 에 있습니다. **배포 패키지를 만드는 일만 하는 자리**이며, 폴더 안내는
`installer/README.md` 에 따로 있습니다.

```
installer/
├── README.md        이 폴더에서 유일하게 손으로 쓰는 파일
├── script/          만드는 데 쓰는 것 (저장소에 남는다)
│   ├── build_installer.bat    ① 모으고 ② 설치 파일을 만든다
│   ├── collect_dlls.bat       실행 파일과 런타임을 stage 로 모은다
│   ├── ClaudeCodeMonitor.nsi  NSIS 스크립트
│   └── version.nsh.in         버전 조각의 원본 (CMake 가 version.nsh 로 만든다)
├── stage/           (생성물) 설치될 파일 그대로의 묶음
└── dist/            (생성물) 완성된 설치 파일
```

```
installer\script\build_installer.bat [빌드디렉터리] [Qt bin 디렉터리]
```

생략하면 `build\ccm-msvc-rel` 과 `C:\Qt\6.8.3\msvc2022_64\bin` 을 씁니다.
사전 조건은 릴리스 빌드와 [NSIS](https://nsis.sourceforge.io) 설치입니다.
어느 디렉터리에서 불러도 됩니다. NSIS 스크립트 안의 경로는 모두 `${__FILEDIR__}`
(스크립트 자기 자리) 기준이라, `makensis` 를 부른 자리에 좌우되지 않습니다.

**어느 DLL 이 필요한지는 손으로 고르지 않습니다.** `windeployqt` 가 판단합니다.
직접 목록을 적으면 Qt 버전이 바뀔 때마다 틀립니다. 수집 후 꼭 있어야 하는 파일
(`Qt6Core/Gui/Widgets/Charts/Network`, `platforms\qwindows.dll`)이 실제로 있는지
확인하고, 없으면 실패로 끝납니다.

### C 런타임은 실행 파일 옆에 둔다

실행 파일과 Qt DLL 이 모두 `MSVCP140` / `VCRUNTIME140` 을 부릅니다. 대상 PC 에
Visual C++ 재배포 패키지가 없으면 실행 즉시 죽습니다.

처음에는 `windeployqt --compiler-runtime` 에 맡겼는데, 그것이 이렇게만 말하고
아무것도 넣지 않았습니다.

```
Warning: Cannot find Visual Studio installation directory, VCINSTALLDIR is not set.
```

**Visual Studio 개발자 프롬프트에서만 동작하는 옵션**이라, 평범한 프롬프트에서
돌리면 조용히 아무 일도 하지 않습니다. 그 사실을 모르면 런타임이 빠진 설치 파일이
만들어집니다. 그래서 그 옵션을 버리고 DLL 다섯 개를 직접 복사합니다.

| 파일 | 크기 | 부르는 쪽 |
|---|---|---|
| `msvcp140.dll` | 545 KB | 실행 파일과 거의 모든 Qt DLL |
| `msvcp140_1.dll` | 35 KB | Qt6Core / Gui / Widgets / Network |
| `msvcp140_2.dll` | 274 KB | **Qt6Gui 하나뿐** |
| `vcruntime140.dll` | 122 KB | 전부 |
| `vcruntime140_1.dll` | 49 KB | 전부 |

`msvcp140_2.dll` 이 빠지기 쉽습니다. 우리 코드는 부르지 않고 Qt6Gui 만 부르는데,
개발 PC 에는 런타임이 깔려 있어 System32 에서 조용히 읽히기 때문입니다. 실제로 한 번
빠뜨렸고, 적재된 모듈 경로를 확인해서 찾았습니다. 그러니 **확인은 "떴는가" 가 아니라
"어디서 읽었는가" 로 해야 합니다.**

```
> (stage 에서 실행한 프로세스의 적재 모듈)
  MSVCP140.dll    ...\stage\MSVCP140.dll      <- 옆에서 읽음. 맞다
  MSVCP140_2.dll  C:\WINDOWS\SYSTEM32\...     <- 시스템에서 읽음. 빠진 것이다
```

`api-ms-win-crt-*` 는 Windows 10 이상의 OS 구성 요소라 챙기지 않습니다.

**`vc_redist.x64.exe` 를 동봉해 실행하는 방법은 쓰지 않습니다.** 25MB 가 늘고,
무엇보다 관리자 권한이 필요해 사용자 단위 설치 도중에 UAC 창이 뜹니다. 권한 없이
끝나는 설치라는 성격이 깨집니다. 옆에 두고 쓰는 것은 마이크로소프트 재배포 조건이
허용하는 방식입니다.

### 소프트웨어 OpenGL 은 담지 않는다

`windeployqt` 는 기본으로 `opengl32sw.dll`(20MB)과 `D3Dcompiler_47.dll`(4MB)을
넣습니다. GPU 가 OpenGL 을 주지 못할 때 쓰는 대역입니다. 이 프로그램은 위젯과 Qt
Charts 만 쓰고 둘 다 래스터 엔진으로 그리므로 한 번도 적재되지 않습니다.

CMake 의 배포 단계는 처음부터 `--no-opengl-sw` 를 주고 있었는데 `collect_dlls.bat`
에는 없어서, 빌드 디렉터리와 설치본의 내용이 서로 달랐습니다. 지금은 둘 다
`--no-opengl-sw --no-system-d3d-compiler` 를 줍니다. **54.3MB 에서 31.7MB 로**
줄었습니다.

### stage 와 zip 배포

`stage/` 는 **설치되고 나면 그 폴더에 놓일 파일들을 미리 그대로 모아 둔 것**입니다.
NSIS 가 거기서 고르지 않고 통째로 집어넣으므로(`File /r`), `stage` 안의 실행 파일을
그 자리에서 바로 실행할 수 있습니다. 빠진 DLL 이 있는지 보는 가장 빠른 방법입니다.

zip 으로 묶어 배포해도 동작합니다. 다만 바로가기와 제거 관리자가 빠지고, 폴더를
옮기면 자동 실행 등록과 statusline 훅이 절대 경로라 끊어집니다. 설정과 이력은 zip
안이 아니라 `%LOCALAPPDATA%` 에 쌓이므로 "포터블" 이라고 부를 수도 없습니다.
자세한 것은 `installer/README.md` 에 적어 두었습니다.

### 사용자 단위 설치인 이유

이 프로그램은 HKCU 의 Run 키에 자기를 등록하고 설정과 이력을 `%LOCALAPPDATA%` 에
씁니다. 즉 애초에 사용자 하나에 매인 프로그램입니다. Program Files 에 깔면 관리자
권한(UAC)이 필요해지는데 그렇게 얻은 권한으로 하는 일이 없습니다. 그래서
`%LOCALAPPDATA%\Programs\ClaudeCodeMonitor` 에 권한 상승 없이 깝니다.

제거할 때는 파일과 시작프로그램 등록을 지우고, 설정/이력/알림 목록은 **물어보고**
지웁니다. Claude Code 의 `settings.json` 에 등록된 statusLine 훅은 건드리지 않고
안내만 합니다. 남의 설정 파일을 제거 관리자가 말없이 고쳐서는 안 됩니다.

### 배치 파일이 영어인 이유

`script/*.bat` 두 개만 ASCII 로 적혀 있습니다. `cmd.exe` 는 배치 파일을 현재 콘솔
코드페이지로 해석하므로, UTF-8 한글이 들어가면 디코딩 결과에 `|` 나 `&` 가 섞여
주석 줄이 쪼개지고 cmd 가 주석을 실행하려 듭니다. 한글 설명은 이 문서에 둡니다.

## 작업 표시줄 위젯 (검토만, 미구현)

날씨 위젯처럼 작업 표시줄 왼쪽에 사용률이 보이게 하는 것은 **서드파티가 할 수
없습니다.** Microsoft 문서 두 줄이 결론입니다.

> In the current release, only packaged apps can be registered as widget providers.
>
> In the current release, the only supported widget host is the Widgets Board.

즉 작업 표시줄에 온도가 인라인으로 나오는 자리는 Microsoft 자신의 날씨 항목이고,
서드파티 위젯은 **위젯 보드(Win+W) 안**에만 들어갑니다. 그 보드용 위젯을 만들려면
이만큼이 필요합니다.

| 요구 사항 | 내용 |
|---|---|
| 포장 | MSIX 필수. Qt exe 를 그냥 등록할 수 없다 |
| 구현 | Windows App SDK 2.3.1+ 와 C++/WinRT 로 `IWidgetProvider` 구현 |
| 등록 | `Package.appxmanifest` 에 `com:ComServer` + `uap3:Extension` 선언 |
| 화면 | Adaptive Cards JSON (또는 웹 위젯 URL). Qt 위젯을 그릴 수 없다 |
| 배포 | 아이콘/스크린샷 포장, 사용자 설치는 Store 또는 사이드로드 |

지금 구조와 겹치는 부분이 거의 없습니다. 별도 MSIX 프로젝트와 WinRT 코드가
따로 필요하고, 그 provider 가 우리 데이터 파일을 읽는 형태가 됩니다.

**대안은 이미 들어가 있습니다.** 트레이 아이콘에 사용률을 숫자로 그려 두었으므로
작업 표시줄만 봐도 값이 보입니다. 위젯 보드 진출을 실제로 원하시면 별건으로
진행하는 편이 맞습니다.

출처: [Implement a widget provider in a win32 app](https://learn.microsoft.com/en-us/windows/apps/develop/widgets/implement-widget-provider-win32)

### 버전 번호는 CMake 하나에서 나온다

`project(ClaudeCodeMonitor VERSION 1.0.0 ...)` 이 유일한 원본입니다. 거기서 세 갈래로
퍼집니다.

| 받는 곳 | 경로 |
|---|---|
| 코드 (`--version`, 정보 창) | `target_compile_definitions` → `CCM_VERSION_STRING` → `core/Version.h` |
| 실행 파일 속성 (탐색기, 작업 관리자) | `res/ClaudeCodeMonitor.rc.in` → 빌드 디렉터리의 `.rc` 두 개 |
| 설치 관리자 | `installer/script/version.nsh.in` → `version.nsh` (`.nsi` 가 include) |

예전에는 세 곳에 따로 적혀 있었고, 실제로 어긋났습니다. 앱과 설치 파일이 `0.2.0` 인
동안 `ccm_probe --version` 만 `0.1.0` 을 말했습니다. 훅은 손이 덜 가는 자리라 고칠
때 잊기 쉽습니다.

`.rc` 를 실행 파일마다 따로 만드는 이유는 `OriginalFilename` 때문입니다. 한 파일을
둘이 나눠 쓰면 `ccm_probe.exe` 속성에 `ClaudeCodeMonitor.exe` 라고 적힙니다.

`version.nsh` 는 생성물이라 `.gitignore` 에 있습니다. `.nsi` 에서 버전을 직접 고치지
마십시오. 다음 빌드가 덮어씁니다.

## Debug 와 Release

Qt Creator 의 **프로젝트 > 빌드 설정** 에서 고르는 이름이 곧 `CMAKE_BUILD_TYPE`
입니다. 실제로 이 저장소의 두 빌드 디렉터리에 들어간 플래그는 이렇습니다.

| | Debug | Release |
|---|---|---|
| MSVC 플래그 | `/Od /Zi /RTC1` + 디버그 CRT | `/O2 /Ob2` + 릴리스 CRT |
| 전처리기 | `QT_QML_DEBUG` | `QT_NO_DEBUG`, `NDEBUG` |
| `Q_ASSERT` | 동작한다 | 제거된다 |
| `qCDebug` 출력 | 나온다 | **나온다** |
| 링크하는 Qt | `Qt6Cored.dll` (d 접미사) | `Qt6Core.dll` |
| 배포 | **불가**. 디버그 CRT 와 Qt 디버그 DLL 은 재배포할 수 없다 | 인스톨러가 쓰는 것 |
| 중단점·변수 | 정확하다 | 최적화로 줄이 건너뛰고 변수가 안 보인다 |

**디버그 로그가 릴리즈에서도 나온다는 점**이 자주 오해받는 자리입니다. 릴리즈가
정의하는 `QT_NO_DEBUG` 는 `Q_ASSERT` 를 없앨 뿐이고, `qDebug`/`qCDebug` 를 지우는
것은 `QT_NO_DEBUG_OUTPUT` 인데 이 프로젝트도 Qt Creator 도 그것을 정의하지
않습니다. 그래서 위의 디버그 콘솔이 릴리즈에서도 같은 내용을 보여 줍니다.

두 빌드 디렉터리의 **생성기가 다른 것**은 Debug/Release 의 뜻과 무관합니다.
`build/ccm-msvc-rel` 은 Ninja, `build/Desktop_Qt_6_8_3_MSVC2022_64bit_Debug` 는
jom(NMake) 입니다. 키트 설정 차이일 뿐입니다.

`windeployqt` 는 구성에 맞는 DLL 묶음을 가져옵니다(`--debug` / `--release`).
인스톨러는 반드시 릴리즈 빌드로 만듭니다.

| 타깃 | 종류 | 설명 |
|---|---|---|
| `ccm_core` | 정적 라이브러리 | 파싱과 기록. 이후 위젯 타깃이 링크한다 |

## 사용법

모드 선택 옵션은 없습니다. 실행하면 항상 훅으로 동작하며 표준 입력을 기다립니다.

```
ccm_probe.exe [--snapshot <경로>] [--log-level <수준>] [--log-file <경로>]
```

| 옵션 | 설명 |
|---|---|
| `--snapshot` | 스냅샷 파일 경로. 생략하면 기본 경로를 쓴다 |
| `--log-level` | `debug`, `info`, `warning`, `error`. 기본값 `info` |
| `--log-file` | 로그 파일 경로. 생략하면 파일 로깅을 하지 않는다 |
| `--unregister` | 등록된 statusline 훅을 지우고 끝낸다 |
| `--allow-other-copy` | `--unregister` 와 함께. 다른 자리의 복사본도 지운다 |
| `--print-hook-state` | 지금 등록된 것을 알려 주고 끝낸다. **고치지 않는다** |
| `--out` | `--print-hook-state` 의 결과를 적을 INI 파일 경로 |

훅은 화면에 보이지 않는 곳에서 실행되므로, 문제를 추적할 때는 `--log-file` 로
파일 로깅을 켜는 편이 낫습니다.

### statusline 등록 (위젯에서)

**설정 창 > 환경 설정 탭 > `statusline 훅` 의 [훅 등록]** 또는 **도구 > statusline 훅
등록** 메뉴를 쓰면 자동으로 등록됩니다.

환경 설정 탭에 둔 이유는 자동 조회 간격과 같은 자리이기 때문입니다. 둘 다
"사용량을 어디서 얻는가" 에 대한 설정입니다. 자동 조회는 우리가 `claude` 를 부르는
것이고, 훅은 Claude Code 가 우리를 부르는 것입니다. 버튼 옆에는 지금 등록 상태가
나옵니다. 다른 명령이 걸려 있으면 그 명령까지 보여 주므로, 누르기 전에 무엇을
덮게 되는지 알 수 있습니다.

상태를 읽을 때는 `HookRegistrar::state()` 를 씁니다. `registerHook()` 으로
알아보려 하면 등록되지 않은 상태에서 등록해 버립니다.

### 해제 — 우리 것만 지운다

같은 자리의 **[훅 해제]** 또는 `ccm_probe --unregister` 로 지웁니다. 남의 상태줄
설정을 우리 제거 기능이 날리는 일이 없도록, 지우기 전에 실행 파일을 견줍니다.

| 등록된 것 | 판정 | 하는 일 |
|---|---|---|
| 없음 | `NotRegistered` | 알리고 끝 |
| 우리 `ccm_probe` (경로까지 같음) | `ThisApp` | 확인받고 지운다 |
| 이름은 `ccm_probe` 인데 다른 자리, **파일이 있음** | `OtherCopy` | **그 사실까지 밝히고** 확인받은 뒤 지운다 |
| 이름은 `ccm_probe` 인데 다른 자리, **파일이 없음** | `OtherCopy` | **묻지 않고 지운다.** 아래 참조 |
| 남의 명령 | `Other` | **파일을 열지도 않는다.** 그 사실만 알린다 |

**죽은 경로는 묻지 않고 지웁니다.** 등록된 실행 파일이 이미 없으면 그 설정은
누구에게도 쓸모가 없습니다. Claude Code 는 그 명령을 실행하려다 조용히 실패하고,
상태줄은 그냥 빈칸이 됩니다. 로그도 남지 않아 `스냅샷이 없습니다` 와 증상이
구별되지 않습니다. 되살릴 방법도 없으므로 물어볼 것이 없습니다. 파일이 살아 있는
복사본은 지금도 동작 중인 설정이므로 그대로 둡니다.

설치 위치를 옮겼거나, zip 으로 먼저 써 보고 설치했거나, 예전 빌드가 등록해 둔
경우가 모두 여기 걸립니다. 제거할 때 이것이 남으면 프로그램을 지운 뒤에도 상태줄이
이유 없이 비어 보입니다.

`OtherCopy` 를 따로 나눈 이유가 있습니다. 예전 빌드나 다른 설치본이 등록해 둔
것인데, 우리 것이 맞으니 지울 수 있지만 사용자가 모르는 사이에 없어지면 안 됩니다.
그래서 확인 창에 "다른 자리에 있는 복사본" 이라고 먼저 적고 묻습니다.

확인 창에는 무엇을 지우는지 그대로 보여 줍니다. 경로만 적으면 "지우면 무슨 일이
생기나" 를 알 수 없으므로 결과도 함께 적습니다.

```
실행 파일 : ccm_probe.exe
경로      : C:/ws/qt/ClaudeCodeMonitor/build/ccm-msvc-rel/ccm_probe.exe
인자      : --color
설정 파일 : C:\Users\austin\.claude\settings.json

지우면 Claude Code 터미널 아래의 사용률 표시가 사라집니다.
사용량 조회와 알림은 그대로 동작합니다.
고치기 전에 설정 파일을 백업합니다.
```

지울 때는 `statusLine` 항목을 통째로 없앱니다. 빈 객체로 두면 Claude Code 가 명령
없는 상태줄 설정을 들고 있게 되어, 나중에 무엇이 남은 것인지 알기 어렵습니다.

### 지금 무엇이 걸려 있는지 알아보기

```
ccm_probe --print-hook-state [--out <파일>]
```

**고치지 않고 읽기만 합니다.** 제거 관리자가 제거 화면을 그리기 전에 이것을 부릅니다.

종료 코드가 곧 상태입니다.

| 코드 | 뜻 |
|---|---|
| 0 | 등록된 것이 없다 |
| 10 | 이 설치본이 등록한 것이다 |
| 11 | 이름은 같은데 다른 자리의 복사본이다 |
| 12 | 남의 명령이다 |

`--out` 을 주면 같은 내용을 INI 파일로도 적습니다.

```ini
[hook]
state=other-copy
command="C:/예전경로/ccm_probe.exe" --color
executable=C:\예전경로\ccm_probe.exe
exists=0
settings=C:\Users\...\.claude\settings.json
```

**UTF-16LE(BOM 포함)로 씁니다.** 읽는 쪽이 NSIS 의 `ReadINIStr`,
즉 `GetPrivateProfileStringW` 이기 때문입니다. 그 API 는 BOM 이 있는 UTF-16LE
파일만 유니코드로 읽고, 그 밖에는 시스템 ANSI 코드페이지로 해석합니다. UTF-8 로
쓰면 경로에 한글이 섞였을 때 깨집니다.

`ccm_probe --unregister` 의 종료 코드는 이렇습니다.

| 코드 | 뜻 |
|---|---|
| 0 | 지웠거나, 지울 것이 없었다 |
| 5 | 지울 수 있었지만 두었다 (남의 것이거나 다른 복사본) |
| 6 | 고치지 못했다 |

제거 관리자가 이 값으로 무슨 일이 있었는지 알립니다.

주고받는 절차(충돌 확인, 결과 안내)는 `ui/HookSetup` 한곳에 있습니다. 메뉴와 설정
창이 같은 것을 부릅니다. 두 벌로 두면 한쪽만 고쳐질 수 있고, 그때 한쪽은 백업 없이
남의 설정 파일을 덮어쓰게 됩니다.

등록기는 다음 순서로 동작합니다.

1. 실행 파일과 같은 디렉터리의 `ccm_probe` 를 대상으로 삼는다.
   (실행한 빌드가 자기 자신을 등록하므로 빌드 디렉터리를 고를 필요가 없다)
2. `--version` 으로 **실제 실행되는지 검증한다.** 실패하면 등록하지 않는다.
3. 이미 다른 `statusLine` 설정이 있으면 확인 후에만 교체한다.
4. 쓰기 전에 `settings.json.bak.<타임스탬프>` 로 백업한다.

`CLAUDE_CONFIG_DIR` 환경변수가 있으면 그 경로의 `settings.json` 을 대상으로 합니다.

**명령은 슬래시 경로를 따옴표로 감싼 형태로 적습니다.** Claude Code 는 statusline
명령을 셸에 넘기는데, 윈도우에서도 그 셸이 bash 입니다. 역슬래시 경로를 그대로
적으면 bash 가 이스케이프로 먹어 `C:wsqt...` 가 되어 명령을 찾지 못하고, 훅이 한 번도
실행되지 않은 채 상태줄만 비어 보입니다. 이때는 로그도 남지 않으므로 증상이
`스냅샷이 없습니다` 와 구별되지 않습니다.

**Qt 가 JSON 을 다시 쓰면 키가 알파벳순으로 정렬되고 들여쓰기가 4칸으로 바뀝니다.**
JSON 객체는 순서가 의미를 갖지 않으므로 동작은 동일하지만 파일 전체가 재작성됩니다.
그래서 백업이 필수입니다.

### statusline 등록 (수동)

`%USERPROFILE%\.claude\settings.json`

```json
{
  "statusLine": {
    "type": "command",
    "command": "\"C:/ws/qt/ClaudeCodeMonitor/build/.../ccm_probe.exe\""
  }
}
```

기존 `statusLine` 설정이 있으면 덮어쓰지 말고 백업 후 교체하십시오.

경로 구분자는 역슬래시가 아니라 슬래시로, 명령 전체는 따옴표로 감싸십시오.
이유는 위의 등록기 항목과 같습니다.

**settings.json 은 세션 시작 때 읽힙니다.** 등록한 뒤에는 Claude Code 를 재시작해야
훅이 돌기 시작합니다.

## Qt 런타임 배포

Claude Code 는 시스템 PATH 만 가진 상태로 훅을 실행합니다. Qt bin 이 PATH 에 없으면
`ccm_probe` 는 `0xC0000135` (DLL not found) 로 **출력 한 줄 없이** 죽고, 상태줄은
그냥 비어 보입니다.

이를 막기 위해 빌드 후 `windeployqt` 가 자동으로 Qt 런타임을 실행 파일 옆에
배포합니다. 훅 등록기도 등록 전에 실행 검증을 하므로, 배포가 안 된 상태에서는
등록 자체가 거부됩니다.

## 출력 규약

| 스트림 | 내용 |
|---|---|
| stdout | 상태줄 문자열만 |
| stderr | 모든 로그 |

Claude Code 가 statusline 명령의 stdout 을 상태줄로 읽기 때문에, 로그가 stdout 으로
새면 상태줄이 오염됩니다. 이 분리는 선택이 아니라 요구사항입니다.

로그는 파일과 콘솔 모두 UTF-8 로 나갑니다. 진입점이 콘솔 코드페이지를 `CP_UTF8` 로
맞추므로, 로컬 8비트로 쓰면 한글이 깨집니다.

## 종료 코드

| 코드 | 의미 |
|---|---|
| 0 | 성공 (표시할 한도 정보가 없어 상태줄이 비는 경우 포함) |
| 2 | 입력이 비어 있음 |
| 3 | 스냅샷 기록 실패 |

기록에 실패하면 stdout 을 비웁니다. 상태줄 장애가 Claude Code 동작을 방해해서는
안 되기 때문입니다.

## 한국어와 영어

화면 글자는 모두 번역 시스템을 거친다. 지금은 한국어만 나오고, 영어 번역을
채우면 영어 환경에서 영어로 나온다.

### 원문이 한국어다

`tr()` / `QCoreApplication::translate()` 의 원문이 한국어이고, 영어는 번역으로
얹는다. 원문을 영어로 두고 한국어를 번역으로 얹는 방법도 있지만 이 프로그램은
한국어로 먼저 쓰였고, 원문을 뒤집으면 기존 글자를 전부 다시 쓰게 된다.

| 환경 | 결과 |
|---|---|
| 한국어 | 번역 파일 없이 원문(한국어) |
| 영어 | `ClaudeCodeMonitor_en.qm` 이 얹힌다 |

### 컨텍스트 두 가지

| 코드 자리 | 방법 | 컨텍스트 |
|---|---|---|
| QObject 파생 클래스 (`ui/`, `mainwindow`) | `tr("...")` | 클래스 이름 (`ccm::ui::SettingsDialog` 등) |
| 그 밖 (`core/`, `infra/`, 무명 namespace 함수) | `QCoreApplication::translate("ccm", "...")` | `ccm` 하나로 모음 |

`core/` 와 `infra/` 는 QObject 를 쓰지 않으므로 `tr()` 이 없다. 컨텍스트를 파일마다
쪼개면 번역 파일이 잘게 흩어지므로 `ccm` 하나로 모았다.

### 번역 파일 갱신

```
cmake --build <빌드디렉터리> --target update_translations
```

`lupdate` 가 소스를 훑어 `ClaudeCodeMonitor_en.ts` 를 갱신한다. 빌드할 때
`lrelease` 가 `.qm` 으로 바꿔 두 실행 파일에 리소스로 싣는다.

**`SOURCES` 에 `ccm_core` 만 적는 이유가 있다.** 화면 글자의 상당수가
`core/` 와 `infra/` 에 있고 그 파일들은 다른 타깃에 속하므로, 명시하지 않으면
`lupdate` 가 보지 못해 번역 파일이 반쪽이 된다. 반대로 위젯 소스와 훅 진입점은
적지 않는다. `TARGETS` 가 이미 주므로 두 번 적으면 같은 파일을 두 번 훑고,
그때 namespace 를 놓쳐 `UsageChart` 와 `ccm::ui::UsageChart` 처럼 같은 내용이
두 컨텍스트로 나온다.

### 덜 된 번역이 화면에 나오지 않게

`lupdate` 는 새 문장을 `<translation type="unfinished"></translation>` 로 넣는다.
비어 있으면 원문이 나오므로 문제가 없다. 그런데 예전에 손으로 영어를 적어 둔 줄이
`<translation type="unfinished">Refresh now</translation>` 처럼 **글자는 있는데
표시만 덜 됨** 인 상태로 남아 있었고, `lrelease` 는 기본으로 이런 줄도 싣는다.
그래서 한국어 환경인데 아래쪽 버튼 세 개만 영어로 나왔다.

두 곳을 막아 두었다.

1. `ClaudeCodeMonitor_en.ts` 에서 그 줄들을 비웠다.
2. `CMakeLists.txt` 의 `qt_add_translations` 에 `LRELEASE_OPTIONS -nounfinished`
   를 주어, 덜 된 줄은 아예 `.qm` 에 싣지 않는다.

영어 번역을 채울 때는 `type="unfinished"` 를 지워야 화면에 나온다. 번역이 하나도
없는 `.qm` 은 30바이트 안팎이다. 그보다 크면 무언가 실려 있는 것이다.

### 한국어가 목록에 있으면 거기서 멈춘다

`Translations::install()` 은 `QLocale::system().uiLanguages()` 를 앞에서부터 훑어
맞는 `.qm` 을 찾는다. 윈도우는 표시 언어를 여러 개 둘 수 있어서 이 목록이
`["ko-KR", "en-US"]` 인 경우가 흔하다.

한국어는 **원문이므로 번역 파일이 없는 것이 정상** 인데, 그것을 "없으니 다음 후보"
로 다루면 뒤따라오는 `en-US` 가 걸려 영어가 얹힌다. 한국어를 1순위로 둔 사람에게
영어가 나온다. 그래서 목록에서 한국어를 만나면 그 자리에서 원문을 쓰기로 하고
멈춘다.

### Qt 표준 버튼

`QDialogButtonBox::Save` 나 `QMessageBox::question` 처럼 Qt 가 이름을 붙여 주는
버튼은 Qt 자신의 번역 파일(`qtbase_ko.qm`)로 번역됩니다. 그것을 싣지 않으면
`Save`, `Cancel`, `Close`, `Yes`, `No`, `OK` 가 영어로 나옵니다. 화면의 나머지가
모두 한국어인데 버튼만 영어인 것이 그 때문입니다.

**Qt 번역을 싣는 대신 버튼 글자를 직접 적습니다.** Qt 번역을 실으면 버튼 언어가
시스템 로케일을 따라가는데, 이 프로그램의 글자는 로케일이 아니라 우리 번역 파일이
정합니다. 그러면 영어 환경에서 우리 글자는 한국어인데 버튼만 영어가 되는 섞인
화면이 여전히 남습니다. 버튼을 우리 번역 시스템에 넣으면 화면 전체가 언제나 한
언어로 맞고, Qt 번역 파일을 배포에 넣을 필요도 없습니다.

`ui/StandardButtons` 한곳에 모았습니다. 창마다 따로 적으면 한 곳을 빠뜨려
"저장" 옆에 "Cancel" 이 놓입니다.

| 함수 | 하는 일 |
|---|---|
| `localizeButtons(box)` | 버튼 상자의 표준 버튼 글자를 바꾼다 |
| `askYesNo(...)` | 예 / 아니요 질문. 기본 선택은 "아니요" |
| `showInfo(...)` / `showWarning(...)` | 버튼이 "확인" 하나인 알림 / 경고 창 |

확인을 묻는 자리는 대개 되돌릴 수 없는 일이므로, Enter 와 Esc 모두 아무 일도
일어나지 않는 쪽(아니요)으로 걸어 둡니다.

### 번역하지 않는 것

**로그 메시지는 번역하지 않는다.** 진단용이고, 로케일에 따라 글자가 달라지면
로그를 검색해 찾는 일이 어려워진다. 업계에서도 로그는 한 언어로 고정해 둔다.
필요하면 함께 넣을 수 있으니 말해 주십시오.

### 번역한 글자를 static 에 담지 말 것

함수 지역 `static` 은 첫 호출에 한 번만 초기화된다. 번역기가 설치되기 전에 한
번이라도 불리면 그때의 글자가 굳어 그 뒤로 언어를 따라가지 않는다.
요일 이름을 `static QStringList` 에 담아 두었다가 실제로 이 문제를 만났고,
지금은 `switch` 로 매번 돌려준다. (`core/TimeFormat.cpp`)

Qt 를 **동적 링크**로 쓰는 것이 중요합니다. LGPL 모듈은 사용자가 Qt 를 자기 것으로
바꿔 끼울 수 있어야 하는데, DLL 로 옆에 두면 그 조건이 저절로 지켜집니다. 정적 링크로
바꾸려면 조건이 까다로워집니다.

MSVC 런타임 DLL 을 함께 넣는 것은 GPLv3 와 부딪히지 않습니다. GPLv3 제1조가 운영체제의
주요 구성 요소를 "시스템 라이브러리" 로 보아 예외로 두고 있고, C 런타임이 거기에
해당합니다.
