# installer

배포 패키지를 만드는 자리입니다. **NSIS 설치 파일을 만드는 일 외에는 아무것도 두지
않습니다.** 프로그램 소스는 `core/` `infra/` `ui/` 에 있습니다.

```
installer/
├── README.md        이 문서. 이 폴더에서 유일하게 손으로 쓰는 파일
├── script/          만드는 데 쓰는 것 (저장소에 남는다)
│   ├── build_installer.bat      ① 모으고 ② 설치 파일을 만든다
│   ├── collect_dlls.bat         실행 파일과 런타임을 stage 로 모은다
│   ├── ClaudeCodeMonitor.nsi    NSIS 스크립트
│   ├── version.nsh.in           버전 조각의 원본
│   └── version.nsh              (생성물) CMake 가 버전을 채워 만든다
├── stage/           (생성물) 설치될 파일 그대로의 묶음
└── dist/            (생성물) 완성된 설치 파일
```

라이선스 전문(`LICENSE`)은 저장소 뿌리에 있고, `collect_dlls.bat` 이 `stage/` 로
복사합니다. 설치 폴더와 zip 묶음 모두에 들어가야 하기 때문입니다.

`stage/` `dist/` `version.nsh` 는 만들어지는 것이라 `.gitignore` 에 있습니다.
지워도 됩니다. 다시 만들면 됩니다.

## 만드는 법

```
installer\script\build_installer.bat [빌드디렉터리] [Qt bin 디렉터리]
```

생략하면 `build\ccm-msvc-rel` 과 `C:\Qt\6.8.3\msvc2022_64\bin` 을 씁니다.
먼저 릴리스 빌드가 되어 있어야 하고, [NSIS](https://nsis.sourceforge.io) 가 깔려
있어야 합니다.

결과는 `dist\ClaudeCodeMonitor-<버전>-setup.exe` 입니다.

## 시작/마침 화면의 옆 그림

`res\installer-welcome.bmp` 를 씁니다. **`res\make_installer_bitmap.py` 가 만드는
생성물이지만 저장소에 넣어 둡니다.** 설치 파일을 만드는 데 Python 과 Pillow 가
필요해지지 않게 하기 위해서입니다. 그림을 고칠 때만 스크립트를 돌리십시오.

```
python res\make_installer_bitmap.py
```

**직접 만들어 쓰는 이유.** 지정하지 않으면 MUI 가
`%NSISDIR%\Contrib\Graphics\Wizard\win.bmp` 를 쓰는데, 그것은 **4비트(16색)**
이미지입니다. 요즘 화면에서는 디더링 무늬가 그대로 드러나 파란 잡티가 낀 것처럼
보입니다. 우리 것은 24비트이고 프로그램 아이콘과 같은 색입니다.

크기 **164 x 314** 는 MUI 가 정한 자리입니다. 다른 크기를 주면 늘어나거나
잘립니다. MUI 는 이 그림을 제 칸(109u x 193u)에 맞춰 조금 눌러 그리므로, 얇고
작은 글자는 뭉개집니다. 그래서 글자를 굵게, 크게 잡았습니다.

버전 번호는 그림에 넣지 않습니다. 구워 두면 판을 올릴 때마다 어긋납니다.

## 설치 화면이 하는 일

| 화면 | 내용 |
|---|---|
| 환영 | 안내 |
| 라이선스 | GPLv3 전문. 단추는 [동의함] 이 아니라 [다음] 이다 |
| 설치 위치 | 기본값 `%LOCALAPPDATA%\Programs\ClaudeCodeMonitor` |
| 설치 중 | 파일 복사, 시작 메뉴 바로가기, 제거 정보 등록 |
| 완료 | **확인란 두 개** |

완료 화면의 확인란은 둘 다 기본으로 켜져 있습니다.

| 확인란 | 하는 일 |
|---|---|
| 지금 실행 | 설치 관리자를 닫으면서 프로그램을 띄운다 (트레이 상주) |
| 로그인할 때 자동으로 실행 | `HKCU\...\Run` 에 등록한다. 끄면 등록을 지운다 |

자동 실행 확인란은 MUI 가 "추가 정보 보기" 용으로 준비해 둔 두 번째 자리를 빌려
씁니다. MUI 의 완료 화면은 확인란을 두 개까지만 내줍니다.

**끄기를 고르면 프로그램도 스스로 등록하지 않습니다.** 프로그램에는 "처음 실행이면
시작프로그램에 등록한다" 는 길이 따로 있습니다(zip 으로 받아 쓰는 사람을 위한 것).
그대로 두면 설치할 때 끄기를 고른 사람의 선택을 첫 실행이 덮어 버리므로, 설치
관리자가 설정 파일에 첫 실행 표시를 미리 찍어 둡니다.

```ini
[app]
firstRunDone=true
```

다시 설치하면 확인란은 언제나 켜진 상태로 나옵니다. 이전에 꺼 두었더라도 그렇습니다.
MUI 가 확인란의 초기 상태를 화면을 그린 뒤에 덮어쓰므로 이전 값을 읽어 반영할
자리가 없습니다. 설치 후 [설정 > 환경 설정] 에서 언제든 바꿀 수 있습니다.

## 제거

제거 관리자는 설치할 때 함께 만들어져 `uninstall.exe` 로 들어갑니다. 시작 메뉴의
[제거] 와 제어판의 [앱 및 기능] 양쪽에서 부를 수 있습니다.

| 지우는 것 | |
|---|---|
| 설치한 파일 | 실행 파일, DLL, 플러그인 폴더. **`RMDir /r $INSTDIR` 는 쓰지 않는다** |
| 시작 메뉴 바로가기 | |
| 로그인 시 자동 실행 등록 | 지우지 않으면 없는 파일을 가리키는 항목이 시작 앱 목록에 남는다 |
| 시작 프로그램 켜고 끈 기록 | `StartupApproved\Run`. Run 값과 짝이다 |
| 트레이 아이콘 표시 설정 | `NotifyIconSettings` 에서 **우리 실행 파일을 가리키는 항목만** |
| 제어판 등록 정보 | |
| 설정·이력·알림 기록 | **물어보고** 지운다 |
| statusline 훅 등록 | **확인란으로 고른 경우에만** 지운다 |

`$INSTDIR` 를 통째로 지우지 않는 것은, 사용자가 설치 경로를 바꿨을 때 남의 폴더를
지울 수 있기 때문입니다. 설치한 것만 이름으로 지웁니다.

### 트레이 아이콘 표시 설정

Windows 11 은 프로그램이 트레이에 아이콘을 올릴 때
`HKCU\Control Panel\NotifyIconSettings` 아래에 항목을 하나 만듭니다. 아이콘을 항상
보이게 할지 숨길지를 기억해 두는 자리입니다. **프로그램이 사라져도 Windows 는 이
항목을 지우지 않습니다.** 그대로 두면 [설정 > 개인 설정 > 작업 표시줄 > 시스템
트레이 아이콘] 목록에 깔려 있지도 않은 프로그램이 계속 남습니다.

하위 키 이름은 실행 파일 경로를 Windows 가 해시한 숫자라 미리 알 수 없습니다.
그래서 제거 관리자가 하위 키를 하나씩 열어 `ExecutablePath` 를 읽고, 우리 실행 파일을
가리키는 것만 지웁니다. 다른 프로그램의 항목은 건드리지 않습니다.

경로는 두 가지 꼴로 적힐 수 있어 둘 다 견줍니다. 알려진 폴더 아래면 Windows 가 그
부분을 GUID 로 줄여 적기 때문입니다.

```
C:\Users\...\AppData\Local\Programs\ClaudeCodeMonitor\ClaudeCodeMonitor.exe
{F1B32785-6FBA-4FCF-9D55-7B8E7F157091}\Programs\ClaudeCodeMonitor\ClaudeCodeMonitor.exe
```

**지운 결과는 바로 보이지 않을 수 있습니다.** 설정 화면의 목록은 explorer 가 들고
있는 것을 그리므로, 다시 로그인하거나 explorer 를 다시 띄워야 사라진 것이 보입니다.

Windows 10 의 `TrayNotify\IconStreams` 는 손대지 않습니다. 모든 프로그램의 설정이 한
덩어리 이진 값에 들어 있어 우리 것만 떼어낼 수 없습니다. 지우려면 통째로 지워야
하는데, 그러면 남의 설정까지 날아갑니다.

**zip 으로 받아 쓰거나 개발 빌드를 실행한 자리는 남습니다.** 제거 관리자는 자기가
설치한 경로만 알기 때문입니다. 손으로 지우려면 `regedit` 에서 위 키를 열어
`ExecutablePath` 가 해당 경로인 하위 키를 지우면 됩니다.

### statusline 훅은 물어보고 지운다

제거 과정에 화면이 한 장 더 있습니다. **[statusline 훅 등록도 함께 지우기]**
확인란입니다.

**화면을 그리기 전에 지금 무엇이 걸려 있는지 먼저 읽습니다.**

```
ccm_probe --print-hook-state --out "$PLUGINSDIR\hookstate.ini"
```

읽는 일도 `ccm_probe` 가 합니다. NSIS 가 JSON 을 파싱하는 것보다 낫고, 우리 것인지
가리는 규칙이 한 곳에만 있게 됩니다. 결과는 UTF-16LE INI 로 받아 `ReadINIStr` 로
읽습니다. 그것이 `GetPrivateProfileStringW` 가 유니코드로 읽어 주는 유일한 꼴이라
경로에 한글이 섞여도 깨지지 않습니다. 창이 번쩍이지 않도록 `ExecWait` 가 아니라
`nsExec::Exec` 로 부릅니다.

읽어 온 상태에 따라 화면의 말과 확인란이 달라집니다.

| 상태 | 화면이 하는 말 | 확인란 |
|---|---|---|
| 등록 없음 | 지울 것이 없습니다 | 꺼짐 · 잠김 |
| 이 설치본의 것 | 이 프로그램이 등록한 항목입니다 | **켜짐** |
| 다른 복사본, 파일 없음 | 없는 파일을 가리켜 상태줄이 빈칸으로 보입니다 | **켜짐** |
| 다른 복사본, 파일 있음 | 지금 이 설치본이 등록한 것이 아닙니다 | 꺼짐 |
| 남의 명령 | 건드리지 않습니다 | 꺼짐 · 잠김 |

어느 경우든 **지금 등록되어 있는 명령을 그대로 화면에 보여 줍니다.** 읽기 전용
입력 칸이라 길어도 끝까지 훑어보고 복사할 수 있습니다. 등록 쪽 확인 창은 경로를
보여 주는데 제거 쪽만 보여 주지 않아, 사용자가 무엇을 지우는지 모르고 누르게 되던
것을 고친 것입니다.

지우는 일은 `ccm_probe --unregister` 가 합니다. 백업도 그 안에 들어 있습니다.
그래서 이 호출은 **파일을 지우기 전에** 합니다. 지우는 일을 할 실행 파일이 아직
있어야 하기 때문입니다.

**다른 자리의 살아 있는 복사본을 지우려면 동의가 필요합니다.** 화면이 그 경로를
보여 주었고 사용자가 그것을 보고 확인란을 켰을 때만 `--allow-other-copy` 를
붙입니다. "모르는 사이에 없어지면 안 된다" 는 조건이 화면에서 이미 채워진
경우입니다.

| 종료 코드 | 제거 기록에 남는 말 |
|---|---|
| 0 | 훅 등록을 지웠습니다 |
| 5 | 이 프로그램이 등록한 것이 아니라 그대로 두었습니다 |
| 그 밖 | 훅 등록을 지우지 못했습니다 |

확인란을 끄면 그대로 둡니다. 마지막 안내도 상태에 맞춰 달라집니다. 등록된 것이
없거나 남의 설정이면 "직접 지우십시오" 를 말하지 않습니다. 지울 것이 없는데 지우는
방법을 알려 주는 것은 틀린 안내입니다.

### 조용한 설치와 제거

```
ClaudeCodeMonitor-1.0.0-setup.exe /S
uninstall.exe /S
```

화면이 없으므로 확인란도 없습니다. 그래서 조용한 설치는 자동 실행을 권장값
(등록함)으로 처리하고, **조용한 제거는 statusline 훅을 남깁니다.**

조용한 **제거**는 설정과 이력을 **남깁니다.** NSIS 는 조용한 모드에서 `MessageBox`
를 띄우지 않고 첫 번째 단추를 누른 것으로 치는데, 그 자리의 첫 단추가 [예] 라
그대로 두면 아무 물음 없이 사용자 데이터가 사라집니다. 지우는 쪽은 되돌릴 수
없으므로 남기는 쪽을 기본으로 삼았습니다.

### 라이선스 화면의 단추가 [동의함] 이 아닌 이유

GPLv3 는 프로그램을 **쓰기 위해** 동의를 받아야 하는 계약이 아닙니다. 받는 사람을
구속하는 것은 복제·배포·개작이고, 그냥 실행하는 데에는 동의가 필요 없습니다.
그래서 "동의하지 않으면 설치할 수 없다" 는 모양새를 피하고, 보여 주기만 합니다.

보여 주는 것 자체는 필요합니다. GPLv3 제4조가 사본마다 라이선스 전문을 함께 주라고
요구하기 때문입니다. 설치 폴더에도 `LICENSE` 가 남습니다.

## stage 는 무엇인가

**설치되고 나면 그 폴더에 놓일 파일들을, 미리 그대로 모아 둔 것입니다.** NSIS 는
여기서 고르지 않고 통째로 집어넣습니다.

```nsis
File /r "${STAGE_DIR}\*.*"
```

그래서 `stage\ClaudeCodeMonitor.exe` 를 그 자리에서 바로 실행할 수 있습니다.
설치본과 같은 파일 구성이므로, 설치 없이 동작을 확인하는 데 쓰면 됩니다.
빠진 DLL 이 있는지 보는 가장 빠른 방법이기도 합니다.

| 들어 있는 것 | 무엇 |
|---|---|
| `ClaudeCodeMonitor.exe` | 본체 |
| `ccm_probe.exe` | statusline 훅 |
| `Qt6*.dll` | Qt 런타임. `windeployqt` 가 고른 것 |
| `platforms\` `styles\` `imageformats\` 등 | Qt 플러그인. 폴더 이름이 곧 약속이라 그대로 두어야 한다 |
| `msvcp140*.dll` `vcruntime140*.dll` | C 런타임. 대상 PC 에 없을 수 있어 함께 넣는다 |
| `LICENSE` | GPLv3 전문. 사본마다 함께 주어야 한다 |

## zip 으로 배포해도 되는가

**됩니다.** 압축을 풀고 `ClaudeCodeMonitor.exe` 를 실행하면 그대로 동작합니다.
다만 설치 파일이 대신 해 주던 일들이 빠지므로, 아래를 알고 쓰는 편이 낫습니다.

| 빠지는 것 | 결과 |
|---|---|
| 시작 메뉴 바로가기 | 사용자가 exe 를 직접 찾아 실행해야 한다 |
| 제어판 [앱 및 기능] 등록 | 목록에 뜨지 않는다. 지울 때 폴더를 직접 지워야 한다 |
| 제거 관리자 | 설정·이력·알림 목록을 물어보고 지워 주는 절차가 없다 |

`LICENSE` 는 zip 안에도 들어 있습니다. 빼고 배포하면 GPLv3 제4조를 어기게 됩니다.

**폴더를 옮기면 두 가지가 깨집니다.** 둘 다 절대 경로로 등록되기 때문입니다.

1. **로그인 시 자동 실행** — 레지스트리 `HKCU\...\Run` 에 그때의 경로가 남습니다.
   폴더를 옮기거나 지우면 없는 파일을 가리키는 항목이 남습니다.
2. **statusline 훅** — Claude Code 의 `settings.json` 에 `ccm_probe.exe` 의 경로가
   적힙니다. 옮기면 훅이 조용히 실패하고, 설정 창 상태가 `다른 명령이 등록됨` 으로
   바뀝니다.

옮긴 뒤에는 설정 창에서 자동 실행을 껐다 켜고, 훅을 다시 등록하면 됩니다.

**설정과 이력은 zip 안에 있지 않습니다.** 어느 쪽으로 배포하든
`%LOCALAPPDATA%\ClaudeCodeMonitor\` 에 쌓입니다. 폴더를 지워도 그것은 남습니다.
USB 에 넣어 다니는 뜻의 "포터블" 은 아닙니다.

그리고 인터넷으로 받은 zip 은 파일마다 **차단 표시(Mark of the Web)** 가 붙어
SmartScreen 경고가 뜰 수 있습니다. 압축을 풀기 전에 zip 속성에서 [차단 해제] 를
체크하면 사라집니다.

## 사용자 단위 설치인 이유

이 프로그램은 HKCU 의 Run 키에 자기를 등록하고 설정과 이력을 `%LOCALAPPDATA%` 에
씁니다. 애초에 사용자 하나에 매인 프로그램입니다. `Program Files` 에 깔면 관리자
권한(UAC)이 필요해지는데, 그렇게 얻은 권한으로 하는 일이 없습니다. 그래서
`%LOCALAPPDATA%\Programs\ClaudeCodeMonitor` 에 권한 상승 없이 깝니다.

제거할 때는 파일과 시작프로그램 등록을 지우고, 설정·이력·알림 목록은 **물어보고**
지웁니다. Claude Code 의 `settings.json` 에 등록된 statusLine 훅은 건드리지 않고
안내만 합니다. 남의 설정 파일을 제거 관리자가 말없이 고쳐서는 안 됩니다.

## 왜 배치 파일만 영어인가

`script\*.bat` 두 개는 ASCII 로만 적혀 있습니다. `cmd.exe` 는 배치 파일을 현재 콘솔
코드페이지로 해석하므로, UTF-8 한글이 들어가면 디코딩 결과에 `|` 나 `&` 가 섞여
주석 줄이 쪼개지고 cmd 가 주석을 실행하려 듭니다. 한글 설명은 이 문서에 둡니다.

더 자세한 내용(런타임을 왜 옆에 두는지, 버전이 어디서 오는지)은 저장소 루트의
`README.md` 를 보십시오.
