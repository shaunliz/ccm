# res

프로그램 아이콘과 Windows 리소스 스크립트.

## 무엇이 원본인가

**그림의 원본은 `ui/AppIcon.cpp` 의 그리기 코드다.** 이 디렉터리의 `.ico` 는
그것으로 한 번 만들어 넣은 산출물이다.

| 파일 | 역할 | 빌드에 들어가는가 |
|---|---|---|
| `ClaudeCodeMonitor.rc` | 실행 파일에 아이콘을 박는다 | 예 |
| `ClaudeCodeMonitor.ico` | 위 스크립트가 읽는 그림 | 예 (`.rc` 를 통해) |
| `make_ico.py` | PNG 들을 `.ico` 로 묶는다 | 아니오 |

창과 작업 표시줄 아이콘은 `.ico` 가 아니라 `ui/AppIcon` 이 그때그때 그린다.
화면 배율에 맞는 크기를 바로 그리는 편이 한 장을 늘려 쓰는 것보다 또렷하다.
탐색기와 설치 관리자는 실행 파일 리소스를 읽으므로 `.ico` 가 따로 필요하다.

## 아이콘을 고친 뒤 .ico 다시 만들기

`ui/AppIcon.cpp` 를 고쳤으면 아래를 거쳐 `.ico` 를 갱신한다.

1. `ui/AppIcon.cpp` 와 `ui/AppIcon.h` 를 링크하는 작은 프로그램으로 크기별
   PNG 를 뽑는다. `appIconPixmap(size).save(...)` 한 줄이면 된다.
   크기는 16, 20, 24, 32, 48, 64, 128, 256 여덟 가지다.
2. `python res/make_ico.py <PNG 디렉터리> res/ClaudeCodeMonitor.ico`
3. 다시 빌드한다.

PNG 를 뽑는 프로그램을 이 저장소에 두지 않는 이유는, 빌드에 쓰이지 않는 코드를
남기지 않기 위해서다. 열 줄이 안 되고 아이콘을 고칠 때만 필요하다.

## 크기마다 다르게 그린다

40px 미만에서는 로봇을 생략하고 꺾은선만 굵게 남긴다. 32px 까지는 로봇의 몸통과
다리가 서로 붙어 형체를 알 수 없는 덩어리가 되기 때문이다. 여러 크기를 늘어놓고
견주어 정한 경계다.
